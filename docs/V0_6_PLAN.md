# CapexGraph v0.6 执行计划

- 目标版本：`v0.6.0 — Point-in-time consensus revisions and expectation-aware regime analysis`
- 状态：待开发；`v0.5.1`发布门禁通过后开始
- 前置依赖：v0.4点时主题宇宙、v0.5官方事件与事实、v0.5.1实时信号
- 最后更新：2026-08-03

v0.6回答的不是“市场发生了什么”，而是“结果相对于当时预期发生了什么变化”。任何
历史结论都必须使用当时可见的预期快照，不能拿今天的共识回填过去。

## 1. 用户路径

```text
配置一个有授权的共识Provider或加载冻结fixture
  → 同步单公司、指标、报告期的点时快照
  → 检查币种、单位、财年、覆盖和陈旧度
  → 计算1/4/12周修正、上调/下调广度和分析师覆盖
  → 将实际值与事件前最后可用共识比较
  → 按当时主题宇宙聚合
  → 在主线雷达中并列查看价格、基本面证据和预期变化
  → 人工决定是否创建或更新研究运行
```

## 2. 不可妥协的数据语义

每条预期观察至少保存：

```text
entity_id / ticker / market
metric / fiscal_period / period_end
estimate_value / currency / unit
analyst_count / high / low / median / mean
provider / provider_version / external_id
valid_at / known_at / observed_at
source_hash / entitlement_class
```

- `valid_at`表示Provider称该快照适用的时刻；
- `known_at`表示该数据何时对授权用户可见；
- `observed_at`表示CapexGraph何时实际采集；
- 历史回放默认按`observed_at`截断，并同时保留`known_at`；
- 同一实体、指标、报告期和观察时刻的修订只追加，不覆盖；
- 没有历史快照时只显示“当前共识”，不得伪造修正曲线；
- 原始授权响应留在本地忽略目录，公开仓库只保留合成的licensed-shaped fixture。

## 3. 规范化范围

首版指标采用白名单：收入、营业利润、EBITDA、净利润、EPS、CapEx和自由现金流。
每个市场适配器负责：

- 财年与自然年、季度与累计口径；
- 拆股后的每股指标；
- 报告币种、显示币种和明确的汇率时间点；
- GAAP/IFRS/本地准则以及调整后指标的标签；
- 分析师数量、缺失区间和Provider计算方法。

不可可靠映射的指标进入`unsupported`或`needs_mapping`，不由模型猜测。

## 4. 实施顺序

### M0 — 契约、迁移和Provider能力

- `EstimateSnapshot`、`EstimateRevision`, `ActualSurprise`和质量结果；
- migration 13起的追加式表和索引；
- entitlement、历史深度、市场、指标、频率和延迟能力矩阵；
- 无密钥冻结fixture和凭证脱敏状态。

退出条件：新装与schema 12升级幂等，旧运行、主题、事件、事实和实时信号计数不变。

### M1 — 单实体点时共识纵切

- 先接一个明确授权且提供历史快照的Provider；
- 增量同步、重试、速率限制、原始哈希和无静默fallback；
- 单实体/指标/报告期的`as_of`查询；
- 1/4/12周绝对与百分比修正。

退出条件：冻结响应证明同一报告期的多次修订可被历史回放，当前值不会泄漏到过去。

### M2 — 覆盖、广度和质量

- 上调、下调、持平和新覆盖数量；
- 分析师数量、陈旧度、离散度和贡献者覆盖；
- 单位、币种、报告期和拆股冲突阻断；
- Provider之间只做并列差异报告，不混成虚假“真值”。

### M3 — 实际值、预期差与事件窗口

- 只使用Evidence链接的官方实际值；
- 选择公告前最后一个可见共识快照；
- 计算绝对/百分比surprise及公告后价格反应；
- 保留公告、修订、实际值和行情各自的来源与时间。

### M4 — 主题聚合与主线融合

- 使用当日点时主题宇宙；
- 等权、中位数和显式权重三种方法；
- 每个聚合结果展示贡献者数量、覆盖率、权重和缺失值；
- 在Mainline Desk并列显示价格确认、基本面证据、预期修正；
- 不自动修改v0.4实验政策，新增特征先作为解释层和候选政策输入。

### M5 — Cockpit、调度与发布

- 共识Provider连接与授权状态；
- 单公司修订时间线、报告期矩阵、surprise卡片；
- 主题修正广度、覆盖和贡献者钻取；
- 幂等盘后/事件后任务，不默认触发模型费用；
- 完整Python、API、CLI、Web、wheel、迁移和桌面/窄屏验收。

## 5. 产品决策门

开发M1前必须明确：

1. 首个Provider及套餐是否允许本地持久化历史快照；
2. 是否允许在个人开源应用中展示聚合值；
3. 覆盖市场、历史深度、频率和调用额度；
4. 默认币种与财年显示规则；
5. 哪些调整后指标可以和官方GAAP/IFRS实际值比较。

如果Provider只给当前共识，系统可以做当前面板，但不能宣称完成v0.6的点时修正目标。

## 6. Definition of Done

- [ ] 至少一个真实Provider纵切和一个公开可提交的冻结fixture；
- [ ] 历史查询无未来函数，当前共识不会冒充历史；
- [ ] 修正、广度、覆盖、陈旧度和离散度确定性计算；
- [ ] 实际值只来自Evidence链接的官方事实；
- [ ] surprise使用事件前最后可见共识；
- [ ] 主题聚合使用同日点时成员并披露贡献者与权重；
- [ ] Provider授权、缺失和失败在CLI/API/Cockpit一致可见；
- [ ] 默认任务无模型费用且不会自动改变研究判断；
- [ ] no-key、迁移、全量测试、Web、wheel和浏览器验收通过。

## 7. 明确不属于v0.6

- 自动下单、仓位管理和投资组合优化；
- 用LLM生成分析师共识或补齐缺失历史；
- Catalyst Scan和跨运行图记忆（v0.7）；
- 将实验主线阈值自动升级为生产投资规则；
- 在公库重新分发未经授权的原始券商/数据商预期数据。

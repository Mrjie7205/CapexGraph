01 / Product decision

先把角色分清，
再谈实时。

这不是给现有 Sources 页面多加一个新闻列表，而是增加一层独立的“市场信号系统”。它负责发现和解释时效性，不拥有事实最终裁决权。当前的公司官方事件、日线历史和 Evidence 账本继续保持各自边界。

实时性不能绕过证据门禁
D1 / INPUT

双通道，同等优先

Jin10McpPollSource 与 Jin10OpenWebSocketSource 都是正式信息通道。前期 MCP 先上线，WebSocket 适配器同步开发；双开后两路持续运行，以观察记录合流，不发生主备切换。

D2 / TRUST

信号不是证据

金十快讯、日历和行情属于发现与市场环境层。它们可以触发研究，但不能直接让供应链关系进入中高置信度；官方公告捕获与人工审核仍是 Evidence 入口。

D3 / ACTION

建议必须带条件

AI 输出方向、时间窗、触发条件、证伪条件、价格确认和覆盖缺口。默认动作为忽略、观察、补证、重评或建立计划，不产生券商订单。

系统层数据源v0.5.1 职责明确不能做
实时信号层Jin10 MCPJin10 WS两路独立采集突发快讯、宏观公布和获准行情；合流后测量覆盖、延迟与字段差异。不能证明公司披露、客户关系或供应链事实，也不能假定两路内容完全等价。
历史价格层EODHDYahoo fallback日线、相对强弱、事件前后反应和跟踪基线。不提供主题历史真相，也不替代实时快讯。
官方证据层SECCNINFO / DART补证、捕获、哈希、审核和版本化公司事件。不能被聚合商摘要或模型推断替代。
研究判断层RulesOptional LLM相关性、影响路径、优先级、条件式行动和重评提案。不自动下单，不把不确定性藏在一句“买入”中。
02 / System architecture

一条事件，
四层判断。

数据连接、确定性处理、模型判断和用户动作彼此解耦。MCP 与 WebSocket 各有独立 checkpoint、健康度和成本边界；任一路故障只降低该路状态，不会触发通道角色切换。浏览器通过 CapexGraph 的 SSE 接收合流后的提醒，金十凭证永远只存在后端。

Inspect channel
首发运行：MCP → Gateway → Rules → AI → Verification → SSE稳定形态：MCP ∥ WebSocket → Observation match；两路同级、持续消费、分别计量
SIGNAL
市场信号金十快讯、宏观数据、跨资产报价；可快，不可直接定案。
PROPOSAL
研究提案规则和模型形成方向、路径、动作与缺口；版本化、可追溯。
EVIDENCE
官方证据监管/公司原文经过安全捕获、哈希和人工审核后进入账本。
DECISION
用户决定研究者接受、忽略、重评或建立计划；系统不提交订单。
为什么不复用 CorporateEventVersion？

公司官方事件是证据化系统对象；聚合快讯可能修订、重复、误传或只有二手摘要。v0.5.1 新增独立的 LiveSignalVersion 与 ResearchActionProposal，只有找到官方原文后，才通过现有 SourceSuggestion → Evidence → CorporateEventVersion 链路升级。

每一关都产生可检查状态，任何失败都不能被“AI 已分析”掩盖。低相关事件在规则层结束；高价值事件才消耗模型费用和官方补证成本。

接收MCP 拉取与 WS 推送分别写入 observation；各自记录 channel、external_id、published_at、observed_at。

合流同一事件的双通道观察合并到一个 signal_key；重放、修订和来源差异仍完整保留。
筛选主题、实体、重要度、新颖度、静默期和排除词；无需模型 Key。

05 / User operations

用户怎么用，
从第一天讲清楚。

v0.5.1 保留渐进式安装，但不建立主备等级：没有任何 Key 可跑冻结演示；前期配置 MCP 即可开始真实轮询；WebSocket 适配器同步开发，获得 Secret-Key 后作为第二条同级通道加入持续采集；模型或本地模型只负责可选 AI 增强。

PATH 01

首次连接

  1. 进入 Settings → Data connections。
  2. 先在后端配置 MCP Bearer，并选择自适应轮询计划。
  3. 点击“测试 MCP”，只返回权限、预算和健康状态。
  4. 取得试用后，再配置 CAPEXGRAPH_JIN10_OPEN_SECRET_KEY 并单独测试 WS。
  5. 两个开关彼此独立；启用 WS 不会停掉 MCP。
  6. 最后保存类别、关键词、排除词和静默时段。
PATH 02

每日监控

  1. 启动服务，Gateway 分别恢复 MCP 与 WS checkpoint。
  2. 打开 Live Desk 查看两路新鲜度、调用预算和未读事件。
  3. 普通事件只经过规则层，静默进入信息流。
  4. 高分事件触发 AI 快速分析和浏览器提醒。
  5. 任一路异常只标记该通道 DEGRADED，另一通道继续原频率运行。
  6. 同一事件匹配后只提醒一次，但保留两路观察、延迟和字段差异。
PATH 03

从提醒到研究

  1. 先看来源、时间和验证状态。
  2. 阅读影响路径、价格反应和证据缺口。
  3. 点击“查官方原文”，进入 SourceSuggestion 队列。
  4. 捕获并审核公告后，事件才进入 Evidence。
  5. 选择加入现有 Run 或创建链接重评。
  6. 系统保留原始运行，不用新信息改写历史判断。

08 / Test matrix

实时系统的质量，
藏在断线时。

测试重点不是“收到一条消息”，而是重复、修订、时区、断线、回补、限额、模型失败、浏览器重连和官方补证都不会破坏历史或制造虚假确定性。

测试层必测场景关键断言
契约时间、版本、保留级别、来源、修订与缺失字段。非法信号不进入分析；修订只追加版本。
WebSocket认证失败、心跳、半开连接、退避、断网、乱序、重放。自身状态可见；重连无重复；故障不改变 MCP 的频率或角色。
MCPinitialize、structuredContent、cursor、isError、JSON-RPC error、限额。不以文本为主要解析源；预算不足只降低 MCP 频率，不影响 WS。
跨通道同一事件先由 MCP 后由 WS 到达、反向到达、字段冲突或只在一路出现。只有一个 signal_key；保留全部 observations、差异、延迟和覆盖状态。
规则关键词、排除、实体别名、主题映射、冷却、新旧闻。同一输入与 ruleset 产生相同评分。
AI超时、空响应、schema 错误、提示注入、模型更换。失败不升级置信度；prompt/model/hash 可追溯。
证据快讯无原文、官方源找到、捕获失败、审核拒绝。Signal 永远不自动变 Evidence；审核链保持原语义。
前端SSE 重连、筛选、已读、静音、窄屏、通知权限拒绝。状态准确；关键动作唯一；失败和数据陈旧可见。
迁移/发布新装、旧库升级、黄金案例、Ruff、pytest、Web、wheel、密钥扫描。旧记录不变；no-key 路径工作；公库无凭证和授权原始数据。
09 / Definition of Done

什么叫真的完成。

单独出现 WebSocket 客户端、新闻卡片或模型摘要都不算完成。真实用户路径、断线恢复、成本与密钥边界、证据门禁和无 Key 回归必须同时成立。

同级双通道MCP 与 WebSocket 可独立启动、同时运行并分别显示真实状态；不存在隐含主备。
一次提醒、两路谱系重放、断线和跨通道合流有确定性测试；匹配后不重复提醒但不丢来源差异。
密钥后端隔离API、日志、manifest、HTML、浏览器和 Git 都不出现凭证。
许可驱动留存正文保留由 retention_class 决定，默认不归档授权不明数据。
规则路径无模型 Key用户仍能获得过滤、主题映射、重要度和人工研究入口。
AI 失败可见模型、版本、成本、超时、重试和结构错误进入审计。

10 / Risks & controls

把失败设计在
成功之前。

主要风险来自供应商权限、实时连接、资讯噪声、模型过度解读和 24 小时运行。每个风险必须有前端状态、持久化状态和测试，不只写在日志里。

R1 · Access

试用权限未获批

MCP 先承担真实运行；WebSocket 适配器继续用冻结协议和 mock server 开发，只有 live smoke 等待 Secret-Key。权限缺失不把 MCP 降格为兜底。

R2 · Disconnect

长连接静默失效

WS 使用心跳、新鲜度阈值、退避重连和独立 checkpoint；前端只把 WS 标为 DEGRADED，MCP 继续按自身计划轮询。

R3 · Duplicate

双通道造成重复提醒

每路先保存 observation，再以外部 ID、时间、规范化文本和内容哈希匹配 signal；提醒、分析和用户动作分别幂等。

R4 · Noise

每条快讯都调用模型

确定性 L0 评分、主题白名单、排除词、冷却和 selective 模式；默认模型费用关闭或受阈值控制。

R5 · Hallucination

模型把标题变成事实

结构化 evidence_gaps、官方补证、置信度门禁和提示注入清洗；未经审核不能升级关系置信度。

R6 · Runtime

本地电脑关闭后无提醒

v0.5.1 明确要求服务进程持续运行；浏览器通知只在允许时发送，VPS/NAS 常驻部署作为后续运维指南。

M0 / M1 已完成双通道契约、迁移 6、独立 checkpoint、双源冻结流和无 Key CLI 演示；接下来让 MCP 进入真实持续运行，同时用 mock server 完成 WebSocket 适配器。拿到 Secret-Key 后只补 live smoke，稳定形态是两路同级常开。
